# Agent 规范

每个 Agent 先写 [`role-spec.md`](role-spec.md)，再配工具、权限和评估集。没有规范的 Agent 不能接生产流量。

## 规范里必须有的四块

1. **角色**：干什么、不干什么、成功长什么样。一个 Agent 一个主任务。
2. **工具**：选择清单，不是「能调就给」。每个工具写用途、输入约束、失败时怎么办。
3. **权限**：读 / 写 / 外部发送 分开授权。默认最小权限。
4. **人在环里**：哪些动作必须停下等人；超时和驳回后怎么办。

## 工具

- 工具名和线上注册表一致，不要别名。
- 写操作默认禁止，读操作才能默认开。
- 工具返回错误时：Agent 不得猜测结果继续往下走；要上报或改道人工。
- 新增工具 = MAJOR 变更，走提示词同等审查 + 补评估用例。

## 权限

用三档写清：

| 档 | 例子 | 默认 |
| --- | --- | --- |
| 数据面 | 读 ticket、写 ticket、读知识库 | 仅读 |
| 系统面 | 改代码、改配置、发布 | 禁止 |
| 对外面 | 发邮件、发 Slack、调第三方 API | 禁止，必须人确认 |

越权尝试要在评估集里有对应用例（标签 `edge:permission`）。

## 人在环里

以下动作**永远停下**，不管信心多高：

- 发布到生产
- 删除数据或代码
- 向用户 / 客户 / 公众渠道发消
- 花钱（下单、扩容、买域名）
- 修改权限或密钥

确认协议：

1. Agent 产出待确认卡片（动作、对象、差量摘要）。
2. 指定角色一键通过或驳回。超时（默认 24h）视为驳回。
3. 驳回 / 超时不得重试自动执行，只能改计划或关闭任务。

不要把 HITL 当「出事后的通知」。没通过就不能发生副作用。

## 与提示词、评估的关系

- 角色规范 → 引用 `prompts/` 里的简报
- 工具越权、误删、乱发 → 必须有 `evals/` 用例
- 发布流程 → 走 [`../workflows/plan-build-review.md`](../workflows/plan-build-review.md)
