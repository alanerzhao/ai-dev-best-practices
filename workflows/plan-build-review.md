# 计划 → 实现 → 审查 → 发布

复制本清单到 PR 或任务票。没打钩的项不能合并。

---

## 0. 入口

- **任务 ID**：
- **类型**：`prompt` | `agent` | `eval` | `app` | `infra`
- **级别**：MINOR / MAJOR
- **拥有者**：
- **回滚方案**（MAJOR 必填）：怎么切回旧版本 / 旧模型

## 1. 计划

写完再动手。Agent 可以贴草案，人要签「做 / 不做」。

- [ ] 目标：这次发完后用户能多做什么
- [ ] 不做：
- [ ] 改动清单（文件路径或组件）：
- [ ] 影响面：提示词 / 工具 / 权限 / 模型 / 评估集
- [ ] 评估计划：跑哪些集合、门槛是多少
- [ ] HITL：本次是否触及发布 / 删除 / 对外发消 / 花钱

**出口**：产品或技术负责人回复「LGTM，可以实现」。

## 2. 实现

- [ ] 按简报改，不扩大边界
- [ ] 提示词 / 角色规范 CHANGELOG 已写
- [ ] 版本号已升
- [ ] 新失败模式已补成评估用例
- [ ] 本地或 CI 跑完 golden + regression
- [ ] 贴结果摘要（通过数 / 失败 ID / 与旧版差）

**出口**：PR 打开，标题带版本号。

## 3. 审查

| 谁 | 看什么 | 签字 |
| --- | --- | --- |
| 工程 | 工具权限、越权用例、回滚、评估数字 | |
| 产品 | 边界、文案、HITL 是否被绕过 | |

审查不通：

- 评估未过门槛
- 新增写工具但没有 HITL
- 线上配置与仓库规范不一致
- CHANGELOG 空

**出口**：两个签字齐（MINOR 可只要工程）。

## 4. 发布

这一步**必须人按**。Agent 只能准备卡片。

- [ ] 发布人：
- [ ] 时间窗：
- [ ] 切换的具体对象（提示词版本 / 模型 ID / 配置项）：
- [ ] 回滚命令已验证（写在下面）：
- [ ] 观察负责人和 48h 看板：

发完后仓库状态改为 `prod` 或 `frozen`。

## 必须人工确认的动作

不管信心、不管是否紧急，以下动作不能由 Agent 自执行。

| 动作 | 为什么 | 谁按 | 没人按则 |
| --- | --- | --- | --- |
| **发布**到生产 / 对外可见 | 不可逆或影响用户 | 产品或 on-call | 任务停在「待发布」 |
| **删除**数据、代码、配置、评估用例 | 丢失不可逆 | 工程 owner | 任务停在「待确认删除」 |
| **对外发消**（邮件、Slack、公众号、客户票） | 警务 / 品牌 / 误伤 | 产品 | 只保草稿，不发送 |
| 花钱 | 财务 | 负责人 | 不下单 |
| 改权限 / 密钥 | 安全 | 工程 owner | 不改 |

确认卡片至少包含：动作、对象、差量、回滚方式、超时后默认驳回。

## 发坏了

1. 先回滚，再排查。不要在生产上现改提示词。
2. 用实际输入补一条 failure 用例，owner 当天挂上。
3. 修好后走回本流程，不要 hotfix 直出。
