# 工作流程

AI 功能和普通功能一样走发布流程，多三样东西：提示词要版本、评估要跑通、部分动作必须人按。

标准路径：[`plan-build-review.md`](plan-build-review.md)。

## 工作怎么流

```text
需求 / 故障
    → 任务简报（prompts/task-brief.md）
    → 角色规范（若是 Agent）
    → 计划（改什么、不改什么、怎么验）
    → 实现
    → 跑评估（golden + regression）
    → 审查（产品 + 工程）
    → 发布（人确认）
    → 观察 48h（新失败入集）
```

## 谁做什么

| 阶段 | 产品 | 工程 | Agent（若有） |
| --- | --- | --- | --- |
| 简报 / 边界 | 主责 | 补约束 | 不得自定义边界 |
| 计划 | 确认做不做 | 拆任务 | 可产出草案 |
| 实现 | 抽查拷贝质量 | 主责 | 按计划改代码 / 提示词 |
| 评估 | 定门槛、抽查自由文本 | 跑集、贴结果 | 可跑，不得改 golden |
| 审查 | 签业务 | 签工程 | 不得自审自合 |
| 发布 / 删除 / 对外发消 | **人按** | 准备回滚 | 产出卡片，等待 |

## 不能跳过的门

- 没有简报不写提示词
- 没有评估结果不合并 PR
- 没有人确认不发布、不删除、不对外发消
- 线上版本与仓库不一致不算发完

## 小改动 vs 大改动

| | 小改动（MINOR） | 大改动（MAJOR） |
| --- | --- | --- |
| 例子 | 补约束、修文案、补 1 个工具读接口 | 换模型、换输出结构、新写操作、改边界 |
| 计划 | 可以很短 | 必须写明回滚 |
| 评估 | regression 全跑 | golden + regression，出新旧对比 |
| 审查 | 工程 1 人 | 产品 + 工程 |
