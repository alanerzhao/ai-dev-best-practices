# 提示词（Prompts）

本目录存放**可复制、可回滚、可审查**的提示词。不写经验贴。

一个任务对应一份简报：先填 [`task-brief.md`](task-brief.md)，再写提示词本体。

## 怎么写

1. **一个文件一个任务**。文件名：`{product-or-scene}-{action}.md`，例如 `support-ticket-triage.md`。
2. **文件头必填**：版本、所属产品、拥有者、冻结状态、对应评估集。
3. **提示词本体只写模型会看到的内容**。人读的说明放在文件头或 CHANGELOG，不塞进 system prompt。
4. **约束用否定句**：「不要猜测 ID」「不要自己发布」比「请尽量准确」有用。
5. **输出要定格式**：JSON schema、Markdown 节点或固定字段。模糊输出无法评估。

## 版本号

格式：`vMAJOR.MINOR`，写在文件头。

| 变更 | 例子 | 版本 |
| --- | --- | --- |
| 改了目标、角色、输出结构、工具权限 | 从「归类」变「归类+回复」 | +MAJOR（v1.2 → v2.0） |
| 补约束、补例子、改用词、不改任务边界 | 增加「忽略广告贴」 | +MINOR（v1.2 → v1.3） |
| 错字、排版、注释 | 修正标点 | 不升版，只写 CHANGELOG |

规则：

- 线上跑的那份必须带版本号（环境变量、配置项或文件名）。
- 一次只上一个新版本。不要「边改边看线上」。
- 旧版本保留至少 14 天，或直到新版回归评估过线。

## CHANGELOG

每个提示词文件末尾维护表：

```markdown
## CHANGELOG

| 版本 | 日期 | 作者 | 变更 | 评估结果 |
| --- | --- | --- | --- | --- |
| v1.1 | 2026-08-30 | @name | 禁止猜测 ticket_id | golden 42/42 |
| v1.0 | 2026-08-01 | @name | 首版 | golden 40/42 |
```

变更栏只写**对模型行为有影响的差异**，不写「优化语气」。

## 审查

改提示词和改代码一样走 PR：

| 检查项 | 谁看 |
| --- | --- |
| 任务边界有没变？输出格式破了吗？ | 产品 |
| 约束是否可执行？有没有让模型越权？ | 工程 |
| 对应 golden / 回归集是否有结果？ | 工程（贴出跑评估的段落） |
| 失败案例有没有覆盖这次改动的风险？ | 产品 + 工程 |

审查不通：没有评估结果的 MAJOR 变更；线上版本和仓库不一致；CHANGELOG 空白。

## 何时冻结

冻结 = 这份提示词不再改文字，只能改调用侧（温度、timeout、路由）。

满足以下**全部**才能 freeze：

- 连续 2 个发布周期回归集过线
- 没有开放的 P0 失败案
- 产品和工程各签一次
- 文件头 `status: frozen`

解冻：新开 MAJOR 版本，把触发解冻的失败案写进评估集。

## 与评估的绑定

每份线上提示词必须指向 `evals/` 里的一个集合目录。没有评估集的提示词不能 freeze，也不能上生产。
